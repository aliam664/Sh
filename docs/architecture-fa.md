# معماری فنی «رمزو» نسخهٔ ۲ — مهمان بدون نصب (مرورگر) + اپ میزبان

> سند تکمیلی GDD. تغییر بزرگ نسبت به نسخهٔ ۱: به‌جای «همه اپ نصب کنند»،
> فقط میزبان اپ دارد و مهمان‌ها با مرورگر گوشی‌شان روی همان هات‌اسپات بازی می‌کنند.

---

## ۱. تصمیم‌های کلیدی و دلیلشان

| تصمیم | انتخاب | چرا |
|---|---|---|
| نقش میزبان | اپ اندروید (Kotlin + Jetpack Compose) | سرور باید روی یک گوشی اجرا شود؛ میزبان بازیکن هم هست |
| نقش مهمان | **وب‌کلاینت تک‌فایلی (HTML/CSS/JS خام)** | «بدون نصب» یعنی مرورگر — حتی iOS/سافاری ✅؛ بدون CDN و منابع بیرونی چون شبکه آفلاین است |
| سرور داخل اپ | **NanoHTTPD + nanohttpd-websocket** (دو کتابخانهٔ کوچک ~۱۲۰KB) | HTTP برای سرو کردن وب‌کلاینت و WebSocket برای به‌روزرسانی زنده |
| منبع حقیقت | **`GameCore` خالص-کاتلین** (بدون وابستگی به UI/شبکه) | یک داور واحد برای اپ میزبان و همهٔ مرورگرها؛ تست‌پذیر |
| همزمانی | **یک رشتهٔ منطقی تکی** برای همهٔ اکشن‌ها و رویدادهای WS | بدون قفل/Race در منطق بازی؛ IO روی رشته‌های خود NanoHTTPD |
| مدل همگام‌سازی | **اسنپ‌شات شخصی‌سازی‌شده** به‌جای پیام‌های ریز رویدادی | ساده، ضدخطا: هر تغییر → ساخت `snapshotFor(pid)` و ارسال به همان بازیکن |
| ورود مهمان | **QR روی صفحهٔ میزبان** (تولید با ZXing core) + تایپ آدرس `http://IP:8080` | دوربینِ خود گوشی QR را می‌شناسد — بدون هیچ اپی |

### پورت و آدرس
- وب‌سرور: `http://192.168.43.1:8080` (پورت `Rules.HTTP_PORT=8080`)
  ریشه `/` → وب‌کلاینت از assets ؛ مسیر `/ws` → WebSocket.

## ۲. جریان داده (مسیر کامل یک حدس)

```
مرورگر مهمان        WebSocket /ws         WebGameServer        GameCore
   │  tap «۵۲۱۱»        │                      │                  │
   ├── {"t":"guess",…} ─┼─▶ onText ─submit──► onLogic( تکی ) ──▶  guess()
   │                    │                      │                  │ (notifyChanged)
   │                    │   broadcastChanged() ◀─render────────◀──┘
   │ ◀── {"t":"snap",…} ┼── snapshotFor(pid) ──┘        (اسنپ‌شات شخصی)
   ▼ رندر دوباره (JS)
```

> نکتهٔ طراحی: به‌جای کلی پیام کوچک، **هر تغییر وضعیت = یک اسنپ‌شات تازه برای هر نفر**.
> حجم هر اسنپ‌شات چند کیلوبایت است و روی LAN ناچیز؛ در عوض سازگاری حالت تضمینی است و
> وب‌کلاینت می‌تواند «رندر = تابع خالص وضعیت» بماند.

## ۳. پروتکل WebSocket (JSON در هر فریم متنی)

### اکشن‌های مهمان (مرورگر → سرور)
| پیام | فیلد | توضیح |
|---|---|---|
| `hello` | `name` | ورود به لابی — فقط در فاز LOBBY پذیرفته می‌شود |
| `secret` | `s` | قفل‌کردن رمز (فقط صاحب رمز، فاز WAIT_SECRET) |
| `guess` | `g` | حدس (فاز OPEN) |

### پاسخ‌های سرور (سرور → مهمان)
| پیام | معنی |
|---|---|
| `snap` | اسنپ‌شات کامل وضعیت از دید همان بازیکن (ساختار پایین) |
| `err` | `code`: `room_full` / `game_started` / … — سپس سوکت بسته می‌شود |

### ساختار `snap` (مهم‌ترین قرارداد)
```json
{
  "t": "snap",
  "view": "lobby | secret | game | spectate | result | final",
  "you":   {"id":3,"name":"سارا","holder":false,"host":false,
            "left":8,"solved":false,"secret":"1125?"},   // secret فقط برای صاحب رمز
  "players":[{"id":0,"name":"علی","host":true}],
  "round":2, "total":5, "holder":"رضا", "max":12, "open":true,
  "history":[["5211",[1,1,1,1],false]],                  // جدیدترین اول — فقط حدس‌های خودم
  "progress":[{"id":3,"name":"سارا","used":4,"solved":false}],
  "result": {"winner":3,"name":"سارا","holderPoint":false,
             "void":false,"secret":"1125","last":false},  // فقط در فاز نتیجه/فینال
  "scores":[{"id":0,"name":"علی","score":1}],
  "champions":["علی"]                                     // فقط در فینال
}
```

**اصول صداقت حفظ‌شده از نسخهٔ ۱:** رمز فقط به صاحب رمز برمی‌گردد؛ محتوای حدس دیگران هرگز
در اسنپ‌شات شما نیست (فقط تعداد/وضعیت حل‌شده)؛ داوری فقط در GameCore روی گوشی میزبان.

## ۴. مدیریت حالت‌های خاص (سیاست‌های v2)

- **اتاق پر / وسط بازی:** در `hello` کد `room_full` / `game_started` و بستن مؤدبانهٔ سوکت.
- **قطع‌شدن مهمان وسط دور:** حدس‌هایش «مصرف‌شده» تلقی می‌شود (دور قفل نمی‌شود).
- **رفتن صاحب رمز وسط دور:** دور باطل و دور بعدی با نفر بعدی.
- **بستن اپ میزبان:** سرور متوقف می‌شود → مرورگرها وارد حلقهٔ «تلاش برای اتصال مجدد» می‌شوند.
- **ماکسیموم هم‌زمانی WS:** ۴ مهمان + میزبان (سبک‌تر از ظرفیت NanoHTTPD).

## ۵. نگاشت کد ⇄ معماری

```
app/src/main/java/com/ramzo/game/
├── MainActivity.kt            ورودی اپ میزبان
├── GameViewModel.kt           پل GameCore ⇄ Compose (رندر اسنپ‌شات برای میزبان)
├── game/
│   ├── Rules.kt               ثابت‌ها (پورت‌ها، قواعد، کدهای خطا)
│   ├── Evaluator.kt           داور دوپاس رنگ‌بندی (بدون تغییر — تست واحد دارد)
│   └── GameCore.kt            ⭐ هستهٔ معتمد: بازیکن، دور، رمز، حدس، امتیاز، قهرمان
├── net/
│   ├── NetUtils.kt            پیداکردن IP محلی (رنج هات‌اسپات)
│   └── web/WebGameServer.kt   ⭐ وب‌سرور: HTTP / + WS /ws + snapshotFor()
└── ui/                        تم، کامپوننت‌ها (با QrCode)، صفحه‌های اپ میزبان
app/src/main/assets/web/index.html   ⭐ وب‌کلاینت مهمان‌ها (تک‌فایل، RTL، آفلاین)
```

## ۶. چرا این مدل برای «بدون نصب» درست‌ترین است؟

| گزینهٔ دیگر | چرا کنار گذاشته شد |
|---|---|
| Captive Portal خودکار (بالاآمدن صفحه پس از اتصال به هات‌اسپات) | نیازمند کنترل DNS/NAT گوشی = روت/فریمور — بدون روت غیرممکن |
| مهمان هم PWA-install شود | باز هم «نصب» است — خلاف خواسته |
| WebRTC | پیچیدگی بی‌مورد؛ WS کافی است روی LAN |
| سرور جدا (لپ‌تاپ/رزبری) | یک دستگاه اضافه، خلاف «فقط چند گوشی» |
